# 多人战斗 SL：本地游戏 v0.111.0 接口调查

范围：只支持当前战斗的 SL，不提供多人整局浏览/回放。所有参与者安装相同版本模组。本文件是实现设计，不代表功能已启用或联机验证通过。

## 接口证据

- ActionQueueSynchronizer.RequestEnqueue：客户端发送请求，主机确认后广播；主机本地提交时 EnqueueAction(action, _netService.NetId) 使用自己的玩家身份。
- 私有 EnqueueAction(GameAction, ulong actionOwnerId) 可以指定归属并广播，因此主机代发某些基础动作在技术上可探索，但不能据此认定可以完整代操所有玩家。
- PlayerChoiceSynchronizer.SyncLocalChoice 的消息只有 choiceId/result；接收端按 senderId 找玩家。主机不能通过普通接口代其他玩家发送选牌结果。
- PlayerChoiceReceived 提供所有玩家的选择结果；主机可统一记录，无需所有客户端各自重建权威顺序。
- ActionExecutor.BeforeActionExecuted / AfterActionExecuted 提供执行边界。等待选牌的动作可能暂停、让队列处理其他动作，再恢复；仅记录出牌或点击的先后不足以还原。

## 建议方案

主机保存全队权威执行日志，每个动作包括玩家稳定身份、战斗/尝试标识、全局序号、轮次、卡牌和目标、药水、选牌及动作暂停/恢复关系。客户端可保留副本，但不独立排序。

全员准备与版本/战斗一致性校验后，主机分发选定尝试与停止轮次。主机协调进度，各客户端只提交自己角色的动作和选牌，继续使用游戏原生动作/选择同步。以实际执行和选择结算驱动下一步；暂停动作要按照原有交错关系推进，不可简单等待每张牌彻底结束后才放行其他玩家。

停止点沿用单人习惯：目标轮的已记录操作全部完成，停在提交结束该轮的动作之前。应特别处理有人先结束回合、其他人继续出牌的情况，不得提前推进敌方回合。回放完以前轮次需复现所有玩家的结束回合顺序。

多人 UI 仅保留战斗 SL：主机选择尝试及停止轮次，其他玩家显示同步状态；任意人停止、掉线、版本不一致、手动动作冲突或状态分歧时全队停止。需要自定义消息的版本握手、序号去重、过期战斗消息拒绝、超时和停止广播，不能直接解除现有单人限制。

验证需至少两个真实客户端，覆盖交错出牌与伤害依赖、选牌期间另一玩家操作、药水目标、多玩家相同角色、先结束回合、重复 SL、停止/掉线/不同模组版本。尚未进行这些联机测试。
